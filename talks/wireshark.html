Understanding
Networks & Wireshark

A beginner's guide to network fundamentals, packet analysis - and what stays visible even when traffic is "encrypted."

What is Ethernet?

The simplest way to get onto a network: a cable. You click an Ethernet cable into your laptop, TV, or router using the familiar RJ45 plug.

It's just the wired version of Wi-Fi - same idea, only the data runs through a wire instead of the air.

Each device has its own MAC address - a unique name tag - so the data arrives at the right device.

Plug in, send your data down the wire, and it reaches the device with the matching name tag.

What is a Network?

Devices connect to share data. They break information into small units called packets that travel across wires or wireless links.

Clients request services (laptops, phones); servers provide them (web, email, files).

Every packet carries a source and destination address, then hops from router to router across the world - like mail moving through sorting centers - until it reaches the right device.

A packet is an envelope: the contents may be sealed, but the addresses outside are always readable.

The OSI Model - Layers 1–3

The OSI model splits communication into 5 layers so each can change independently (modularity), hide the one below (abstraction), and work across any vendor (interoperability).

01

Layer 1: Physical

Raw bits over physical media.

  • Cables, Wi-Fi, fiber, voltage
  • The copper wire laptop→router
02

Layer 2: Data Link

Link transfer via MAC addresses.

  • Ethernet, Wi-Fi, frames
  • Your MAC on the LAN
03

Layer 3: Network

Routes packets across networks.

  • IP addresses, routers, ICMP
  • Your public IP browsing

Layer 4: How Data Is Delivered - TCP vs UDP

Layer 4 chooses how to send: a careful phone call (TCP) or a quick shout (UDP). Hover each step to read what Wireshark shows.

TCP - reliable (the 3-way handshake)

💻 Client🖥️ Server
① SYN →
Packet 1 · SYN3372 → 80 [SYN] Seq=0 Len=0 → "Can we talk?" Client asks to open a connection. No data yet.
② SYN, ACK ←
Packet 2 · SYN, ACK80 → 3372 [SYN, ACK] Ack=1 Len=0 → "Yes - I'm here." Server agrees and acknowledges the request.
③ ACK →
Packet 3 · ACK3372 → 80 [ACK] Seq=1 Ack=1 Len=0 → "Great, let's go." Client confirms. Connection now open.
🔗 connection ready → data flows reliably

Sets up a connection first, numbers every byte, re-sends anything lost, and confirms delivery. Slower, but nothing goes missing. Web, email, file downloads.

UDP - fast (no handshake)

UDP packetUDP just sends - no asking permission, no handshake first.

UDP packetNo ordering - packets may arrive out of order, and that's OK.

no setup · no confirmations · no re-sends

Just fires packets and moves on - no setup, no confirmations, no re-sends. Faster, but some packets may be lost. Video calls, live streaming, gaming, DNS.

Layer 5: Application - where Burp lives

The HTTP request, the page, the DNS question - the app's real data. This is exactly what HTTPS encrypts.

Burp Suite reads it anyway - not by sniffing the wire, but by sitting in the middle as a proxy. Your browser is set up to send everything through Burp.

To open HTTPS, Burp installs its own certificate so the browser trusts it. Burp decrypts, lets you read & edit the request, then re-encrypts and forwards it on.

A man-in-the-middle you set up on purpose - it sees the content, but only for traffic routed through it.

Each wrapper has a name: segment (L4) → packet (L3) → frame (L2). A frame contains a packet contains a segment. HTTPS only encrypts the Application data - every header wrapped around it travels in the clear.

What is Wireshark?

The world's most popular network protocol analyzer. It captures packets crossing the network and shows them in human-readable form - from Ethernet headers up to application data.

Who uses it: network engineers (connectivity), security analysts (threats), developers (protocol bugs), IT (bandwidth).

Where Does Wireshark Operate?

NIC - captures packets at Layer 2 (Data Link).

Promiscuous mode - receives all packets, not just those addressed to it.

Passive listener - never interferes with or modifies traffic.

The critical point: normally a NIC drops packets not addressed to it. In promiscuous mode it keeps everything - that's how Wireshark sees all activity, by observing, never injecting.

What Wireshark Shows

Packet List

Summary per packet: time, source, destination, protocol, length.

Packet Details

Tree of decoded headers per layer - Ethernet → IP → TCP → HTTP.

Raw Bytes

Hex of the actual bytes exactly as they appeared on the wire.

PRIVACY PERSPECTIVE

LAN, WAN & localhost — and broadcast traffic

Three scopes Wireshark can watch: your own machine (localhost · 127.0.0.1), your local network (LAN, behind the router), and the internet beyond it (WAN).

On a LAN, devices broadcast — shout to everyone — to discover each other and announce who they are. Wireshark sees it all; a proxy never does. Search for it:

arp"Who has 192.168.1.5?" — maps every device's IP to its MAC.
dhcpA device getting an IP — often reveals its hostname.
mdns || nbnsBonjour / Windows names — e.g. "Bobs-iPhone", "Living-Room-TV".

Broadcasts let you map a whole network passively — and they leak device names a proxy would never reveal.

What Wireshark catches that Burp can't

🔒 HTTPS hides the content

  • URL path & query
  • Headers & cookies
  • Request / response bodies

👀 …but the connection still leaks

  • Destination IP — who you talk to
  • SNI — hostname, clear in TLS
  • Sizes & timing — fingerprint

Burp only sees HTTP(S) routed through it. Wireshark sees the rest:

🌐 DNS lookups dnsEvery domain a device resolves — Burp shows none. Exposes hidden trackers, telemetry & "phone-home" servers before HTTPS even starts.
⚡ QUIC / HTTP-3 quicModern web traffic over UDP 443 that skips an HTTP proxy entirely — Wireshark still shows the connection and SNI.
📞 WebRTC / STUN stunCan leak your real/local IP and bridge web ↔ app identity over localhost (the Meta localmess case).
🔁 Localhost traffic ip.addr==127.0.0.1Native apps quietly talking to web scripts on your own phone — Meta Pixel / Yandex de-anonymization (2025).
📌 Pinned / proxy-ignoring appsRefuse Burp's certificate — yet destination, SNI & timing still show plainly on the wire.
The pattern: Burp = the content of the web traffic you proxy. Wireshark = every connection that leaves the device, in any protocol. Privacy violations love the traffic a web proxy never sees.

Takeaways

1. Layers matter. Encryption is high (L5); IP/ports/sizes below it are open.

2. HTTPS ≠ private. It hides content, not metadata - SNI, DNS, traffic shape still talk.

3. Wireshark sees what Burp can't: DNS, TLS handshakes, non-HTTP, and connections a proxy never touches.

4. Wireshark is passive - the truth source for "what actually left the machine."
