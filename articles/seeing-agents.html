Seeing Agents: Fingerprinting an AI Agent from the Defender's Side

Everyone in AI security is looking at the payload. I wanted to look at the carrier.

The field's attention is almost entirely on prompt injection, jailbreaks and tool abuse: the malicious content an agent might process. But there is a question that comes before all of those:

Before you ask "is this agent malicious?", you have to answer "is there an agent here at all, and what is it doing?"

That first question is not an alignment problem. It is a detection and fingerprinting problem, and it is the same problem bot-detection research has worked on for a decade. The twist is that a modern LLM agent is neither a human nor a classic script. It sits in an interesting gap between the two, and that gap is measurable.

So I built a small, reproducible lab. It drives a browser through a task the way an AI agent would, records what the page can observe, and prints a side-by-side comparison against a human doing the same task. Everything runs locally: the lab serves its own instrumented page on localhost and never touches a third-party site.

The signal taxonomy

Five families of signals separate the three actors involved: a human, a classic bot, and an LLM agent.

DimensionHumanAI agentObserved via
Automation artifacts navigator.webdriver = false, real plugin and MIME lists webdriver = true, empty plugins, headless user agent client JS
Input humanity hundreds of mouse moves, jitter, off-center clicks, per-keystroke timing near-zero mouse moves, dead-center clicks, values set programmatically client JS
Behavioral cadence reads before acting; noisy, variable timing acts on load; near-zero, flat inter-event timing client JS + timing
Semantic navigation scans, hovers, backtracks goes straight to the right element by role or text, reasoning over the DOM DOM interaction log
Network signature browser-consistent header set and order automation UA, header-order and sec-ch-* anomalies proxy / server headers

What an agent session actually looks like

Measured output from an agent run of the lab, with the reason each number matters:

signal                  agent      why it matters
navigator.webdriver     True       true == automation flag on
navigator.plugins       0          0 is typical of headless/automation
mouse move events       2          humans emit hundreds; agents near-zero
keydown events          29         value set with 0 keys = programmatic fill
median key gap (ms)     0.0        humans ~80-200ms; agents ~0-5ms
key gap variance        0.5        human timing is noisy; machine is flat
click offset (px)       1.2        humans miss center; agents hit dead-center
time to 1st action      50 ms      humans read first; agents act on load

Two mouse movements where a human leaves hundreds. Keystrokes with a median spacing of 0.0 milliseconds and near-zero variance. Clicks landing one pixel from dead center, where a human always misses. A first action 50 milliseconds after page load, with no reading and no hesitation.

None of these are boundaries. Every one of them is spoofable, and that is the same arms race bot detection has been running for years.

The signal that interests me: thinking without looking

A classic bot is fast and blind: it fires actions with no perceptual behavior at all. A human is slow and perceptual: mouse drift, scrolling, reading pauses, hesitation.

An LLM agent is a novel third profile. It pauses to think, because inference latency sits between observe, decide and act. But during that pause it produces none of the perceptual micro-behavior a human emits while deciding. Deliberation without perception.

That gap, not any single flag, is the part worth researching. A user-agent string can be patched and mouse jitter can be synthesized, but an agent cannot fake human-like perception during its thinking pauses without ceasing to work the way an agent works. The durable signals are the ones intrinsic to being an agent.

Honest limitations

  • Every individual signal here is evadable. Automation flags can be patched, timing can be humanized. No single tell is a boundary.
  • Client-side signals assume you can instrument the page. In real deployments the network and proxy-layer signals matter more, because they survive when the endpoint is not yours.
  • A real fingerprint is a fused score over many weak signals, continuously recalibrated. This lab shows the raw signals; productionizing them is the detection-engineering work.

Why this matters now

Enterprise agent-security platforms all start from the same place: discovery and runtime observability. You cannot govern, monitor or enforce policy on an agent you cannot see. Ten years of bot-detection research already knows how to read the fingerprints; the defender's first job in agent security is the same as it was for bots. Know that the non-human actor is there, and know what it is doing.

Before we can govern agents, we have to see them.
